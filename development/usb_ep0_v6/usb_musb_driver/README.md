# Moto G20 MUSB PIO: hub + keyboard implementation

This V4 source revision is validated against a host register/FIFO model and
has not been tested on the phone. It does not demonstrate sustained USB power,
hub enumeration, or keyboard input. An AARCH64 EDK2 build and a new physical
candidate are separate gates.

## Implemented scope

- One MUSB root port; EP0 control requests, including a device behind a
  high-speed hub's single transaction translator (TT).
- Four independent periodic interrupt-IN pipes, keyed by device address and
  USB endpoint address. This allows a hub's status endpoint and a keyboard's
  endpoint to run at the same time, even when both are numbered `0x81`.
- Dedicated hardware RX EP1..EP4 and single-buffered 64-byte FIFOs, at byte
  offsets 64, 128, 192, and 256. EP0 retains bytes 0..63. Every pipe owns its
  target address, TT route, data toggle, interval, buffer, callback, and generation.
- Cancellation, slot reuse, role loss, shutdown, and reset operate on the
  appropriate pipe(s). A canceled/recreated pipe does not receive an old
  completion callback. Register access remains protected at TPL_NOTIFY.
- MUSB TX/RX hub and port registers are programmed for EP0 before SETUP and
  retained through data/status. Interrupt routing is programmed on its own RX EP.
- A translator with hub address zero is direct, including the `{0, 1}` value
  generated by UsbBusDxe for some root-connected full/low-speed devices.

## TT contract and boundaries

Pinned Motorola kernel source:
`261390cdfff66efef9082bd70c1af0abd21d77f2`,
`drivers/usb/musb/musb_host.c` (address calculation around lines 2809..2824,
RX programming around 599..603, TX programming around 964..968), and
`drivers/usb/musb/musb_regs.h` (indexed FIFO and target register layout).

MUSB HUBADDR bit 7 denotes **multi-TT**; it is not a generic split-enable flag.
EFI_USB2_HC_TRANSACTION_TRANSLATOR supplies only a hub address and port number.
The paired local EDK2 `MdeModulePkg/Bus/Usb/UsbBusDxe/UsbHub.c`,
`UsbIsHubInterface` and `UsbHubInit`, uses the default single-TT hub setting;
`UsbEnumer.c` supplies the relevant parent/inherited translator. Consequently
this implementation writes a seven-bit hub address and does not set bit 7.
It does not support switching a hub into a non-default multi-TT alternate
setting. This is a dependency on the paired UsbBusDxe behavior, not discovery
of a hub's physical TT mode by the HC.

Four concurrent pipes is a resource bound, not four guaranteed external ports:
each hub status endpoint and each HID interrupt endpoint consumes one pipe.
A fifth request returns EFI_OUT_OF_RESOURCES; a duplicate active device/endpoint
request returns EFI_INVALID_PARAMETER. High-speed interrupt packets over
64 bytes return EFI_UNSUPPORTED. Bulk, isochronous, synchronous interrupt,
and interrupt OUT remain unsupported; this is not mass-storage or general USB
support. Full-speed hubs use ordinary full/low-speed bus routing, and a keyboard
behind a high-speed hub uses the supplied single-TT split route. Physical timing,
split handling, signal integrity, and hub compatibility remain unverified.

The platform library still owns Type-C role, VBUS, PHY, clocks and shutdown.
The HC is not published until those checks and controller qualification pass.
No USB readiness is inferred merely from installation of a diagnostic protocol.

## Revision 3 cached diagnostics

The resident diagnostic protocol and status payload advertise revision 3 and
the exact structure size. The added `Role` member carries the platform's
revision 2 cached Type-C snapshot, counters, validity/error masks, and calibration
result. Reading this protocol does not read controller or platform MMIO and
does not cause a new role sample, register snapshot, boost attempt, or trim write.
The HC and both platform caches are copied together at `TPL_NOTIFY`, preventing
a role notification from mixing state before and after a transition. Callers
may enter at `TPL_APPLICATION`, `TPL_CALLBACK`, or `TPL_NOTIFY`; their original
TPL is restored on successful retrieval, getter failure, and metadata failure.
This protects the cached copy; platform snapshot fields retain their documented
sampling times and are not simultaneous live hardware measurements.

`GetStatus` propagates a platform diagnostic getter failure. An unsupported role
revision or a role payload size mismatch returns `EFI_INCOMPATIBLE_VERSION`.
On either retrieval error, partial role values are discarded, `ValidMask` is
cleared, and role/snapshot/calibration statuses record the error. The HC status
remains independently available, so a diagnostic retrieval cannot turn an HC
failure into a success. Consumers must check the return status and payload
metadata, then use `ValidMask`, `ErrorMask`, `EfuseValid`, and `TrimApplied` to
interpret values. A zero value alone is not evidence of a successful register
read or calibration.

V3 additionally caches DEVCTL before SESSION, after SESSION then HOST_FORCE,
and after qualification or timeout, together with POWER and OTG_EXT_CSR. The
five-bit validity mask qualifies these historical values. No diagnostic getter
reads the powered-off controller. V4 extends only a qualified new source session asynchronously to1100ms;
both HOSTMODE and the complete DEVCTL VBUS mask must be present. HOSTMODE alone,
VBUS alone, or neither never publish the USB HC protocol. SESSION before
HOST_FORCE follows Motorola `sprd_musb_enable`; this ordering is not established
as the cause or cure of the earlier timeout.

## Bounded recovery after a session timeout

A step 5 `EFI_NOT_READY` stops the controller while it is accessible, then asks
the platform to remove source power and PHY ownership while retaining the role
detector. The failed session snapshot survives this rollback. All HC MMIO stays
disabled until a later successful platform bring-up. The timer queries only
the independent detector every 100 ms while waiting for unplug evidence.

Rearming requires at least 500 ms of elapsed monotonic time with fresh successful
Type-C/EIC samples: EIC VBUS absent and states 0, 3, or 9, including an observed
detached state 0 or 3. An unchanged attached cable, state 9 alone, VBUS present,
an unavailable read, or an interrupted shorter interval cannot rearm. A transport
read error, backwards counter, or rollback error latches fatal for this driver
lifetime. Sampling certifies the observed sequence, not continuous physical
contact between samples. A successful interval allows Init to inspect a later
connection; only the platform's separately qualified source state may enable
power. No forced host role or blind boost is introduced.

The lifetime budget is three **new powered bring-ups reaching SESSION**. Normal
USB HC Reset calls while the controller remains powered do not consume this
budget and remain legal after three successful bring-ups. A failed Reset uses
the same stop, rollback and stable-detach path; no retry is permitted when the
new-power budget is exhausted. Explicit port power-off remains persistent.
Identity, inherited DMA, FIFO, initialization transport and rollback failures
remain fatal rather than becoming automatic retries.

Init and HC configuration now share one outer TPL_NOTIFY guard. This closes the
window where the platform's independent monitor could remove controller clocks
between a successful Init return and the HC's first register access. The guard
is nested by the platform and does not lower the caller's TPL.

## Validation performed

Run `tests/run.ps1`. It compiles the production C file with GCC, real EDK2 X64
headers, `-Wall -Wextra -Werror`, and a host model of indexed endpoint registers,
indexed FIFO allocation registers, FIFO contents, role loss, and TPL callbacks.
The output in `tests/RESULT.txt` contains 51 passing test blocks: 40 inherited controller/diagnostic/recovery
blocks (VBUS-only timeout expectation updated for V4) plus eleven asynchronous
connection regression groups, including:

- EP0 descriptor/short-packet/OUT/no-data stages and stall, timeout, overflow.
- Single-TT control route retained over every stage; root `{0, 1}` direct route;
  invalid TT values rejected without MMIO.
- Simultaneous high-speed hub status and split low-speed keyboard input with
  distinct payloads, toggles, target registers and callbacks.
- Independent cancellation, freed-slot reuse, four-pipe capacity, role loss,
  and stale-generation suppression across a TPL restore.
- No register access after the platform has removed controller power.
- Publication withheld on DMA/controller qualification failure.
- Exact cached role mapping, including counters above 32 bits and failed fields;
  getter failure propagation, revision and size rejection, invalid argument
  handling, and absence of MMIO during diagnostic reads.
- A pending role notification is deferred until the complete diagnostic copy
  finishes; the next retrieval sees the updated caches. Caller TPL is preserved
  on success and both getter/metadata error paths, including nested platform
  getter protection.
- Session and host-force stopped and read back before FIFO reassignment;
  pending activity on unused TX1..15 or RX5..15 rejects takeover without
  modifying endpoint CSRs or FIFO allocation. Inherited peripheral CSR bits
  with overlapping meanings also cause conservative rejection.
- HOST-only and neither fail at 100 ms; VBUS-only with valid source waits
  asynchronously to 1100 ms without publishing, with pre-OFF snapshot
  preservation and SESSION-before-HOST_FORCE assertions in the register model.
- No retry on the same cable, state 9 alone, brief detach, EIC high, or unavailable
  read; a valid 500 ms interval permits exactly one reattachment attempt.
- Three failed powered starts exhaust recovery. Rollback/transport faults and
  counter reversal latch fatal. Public Reset/GetPort while off touch no HC MMIO.
- Eight normal powered HC resets still succeed with the power budget at three;
  a timeout follows the correct exhausted/non-exhausted recovery path.
- A pending platform shutdown at Init's inner TPL restore cannot run until HC
  configuration finishes; no stale HC access follows shutdown.

Controller diagnostic steps are 1 identity, 2 inherited DMA, 3 session/unused
endpoint qualification, 4 FIFO configuration, and 5 host-session startup.
The regression in `tests/takeover_before/REPRODUCTION.txt` failed against
the retained pre-fix source before the two takeover checks were added.

The model supplies completion events: it verifies software behavior and does
not prove that real hardware will produce those events. The phone has not been
accessed or modified as part of this change.

## V4 asynchronous connection experiment

The consumed V3 photo 20260926_113242.jpg showed DEVCTL 0x98/0x99/0x19,
POWER 0x60 and OTG 0x01, no completed transfers, one session/boost, and one
recovery rearm. User clarified that only text repeated after a single LED pulse.
The absence of HM is established; its cause remains unknown.

Motorola's musb_core.h at commit261390cdfff66efef9082bd70c1af0abd21d77f2
defines OTG_TIME_A_WAIT_BCON=1100ms, distinct from the 100ms A_WAIT_VRISE.
musb_start and musb_host_setup do not require HM before arming their Linux host
path. This motivates an experiment; it is not proof of identical silicon timing.

V4 retains the initial100ms qualification, and only a new powered bring-up may
continue asynchronously if SESSION=1, BDEVICE=0, VBUS sense=3, HOST_FORCE=1
and a fresh platform PollRole confirms AttachedSRC/EIC high. During pending,
HC is not ready/published and no USB transfer is allowed. Every callback polls
the platform under TPL_NOTIFY before HC MMIO; a negative result can gate clocks
and therefore skips all subsequent HC cleanup accesses. The platform watchdog
and fault policy remain authoritative. No additional source enable is issued.

The deadline is1100ms from SESSION using the ascending platform performance
counter. A delayed callback checks real elapsed time and rejects even HM if first
observed at/after that deadline. Timer scheduling means physical shutdown can
occur later than the deadline;1100ms is the software qualification window, not
a hard realtime voltage duration guarantee. Counter reversal is fatal. At a
qualified timeout the existing stop/stable-detach/three-attempt policy applies.
Synchronous UEFI Reset retains100ms behavior and cannot leave async work pending.

Diagnostics preserve initial POWER readback and TESTMODE without writing either
new policy, the100ms DEVCTL/POWER/OTG snapshot, latest pre-OFF snapshot, and first
observed HM/FSLS times with validity bits. First times are sampled observations,
not electrical edge measurements. PHY source/order is unchanged from V3.

Eleven new host-model groups cover delayed HM at700ms, scheduling delay beyond
deadline, role loss/previous monitor gate without HC MMIO, monitor deferred at
initial TPL restore, counter reversal, BDEVICE/VBUS/force loss, ExitBoot pending,
and synchronous Reset behavior. These tests supply synthetic hardware events.
